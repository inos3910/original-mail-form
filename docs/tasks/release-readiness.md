## 背景・目的

既存の自由なコード方式を維持し、管理者の編集負担と送信時の待ち時間を改善する。既存修正の検証状況は [レビュー対応記録](../review/complete/review-fixes-20260926.md) を参照する。

## 要件

旧コード方式と管理画面方式、確認ON/OFF、添付、返信OFF、全送信方式の対応表を検証する。管理画面の使い方、関数例、フック、cron設定、障害復旧を文書化する。バージョン・変更履歴・更新互換性を整理する。

## 非対象

- 他タスクの機能実装、GA4ランキングの変更。
- 本番反映、merge、push、リリース公開。

3. 対象機能を既存設計に合わせて実装する。
