# OMF-018 秘密情報の暗号化保存と画面への非表示

- 起票日：2026-10-16
- ブランチ：`feature/secret-storage`（develop から作成）

## 調査結果（2026-10-16）

| 保存場所 | 項目 | 修正前 |
| --- | --- | --- |
| オプション | `omf_recaptcha_secret_key` `omf_turnstile_secret_key` `omf_google_client_secret` | 平文。設定画面の password 欄の value に値をそのまま出力 |
| フォームのメタ | `cf_omf_slack_webhook_url` | 平文。フォーム編集画面のテキスト欄にそのまま表示（編集者も閲覧可） |
| オプション | `_omf_google_access_token` `_omf_google_refresh_token` | 暗号化済み（AES-256-GCM、鍵は `wp_salt('auth')` 由来）・autoload 無効 |
| 送信キュー | 配信ペイロード | 暗号化済み |

対策済みの点：添付は公開領域外（0700）・ID照合で配信、秘密情報の設定画面とエクスポート・インポートは `manage_options`、フォームと送信データは非公開・REST 非公開。

## 決定事項（2026-10-16 利用者確認済み）

1. 上表の平文4項目を、Google トークンと同じ方式（`OMF_Trait_Cryptor` の `v2:` 形式）で暗号化して保存する。既存の平文は最初に読み出した時に暗号化して保存し直す。ソルト変更などで復号できない時は空として扱い、設定画面に再入力が必要な旨を表示する
2. 保存済みの値を画面（HTML）に出さない。「設定済み（末尾4文字：xxxx）」とだけ表示し、入力欄は空。空のまま保存すれば現在の値を維持、「削除する」にチェックで削除、入力があれば置き換え
3. 編集者がフォームと送信データを扱える現在の権限は変えない（専用権限の導入はしない）

## 動作確認結果（2026-10-16・corp-oji）

- 平文で入っていた Turnstile シークレットキーが、設定画面を開いた時点で `v2:` 形式に暗号化され、autoload も無効になった
- 設定画面：HTML に値が出ない（入力欄は空、「設定済み（末尾4文字：xxxx）」表示）。空のまま保存で維持、入力で置換（DB は暗号化）、「削除する」で未設定
- WP-CLI の `update_option` でも暗号化して保存される（当初は管理画面でしかフックが登録されず平文で残ったため修正）
- 復号できない値は「保存済みの値を読み取れません…再入力してください。」と表示
- フォーム編集画面の Slack Webhook URL：保存で暗号化、正しく復号、空のまま保存で維持、「削除する」で削除、HTML に値が出ない
- 既知の既存動作：フォーム編集画面で「更新」すると、バリデーション設定の添付ファイル上限（`file_size`）が 10MB に丸められる（今回の変更とは無関係）
