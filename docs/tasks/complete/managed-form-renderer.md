## OMF-002からの実装引き継ぎ

[共通定義仕様](../../spec/field-schema.md) と `OMF_Field_Schema::read()` を使用する。配列順で表示し、出力をエスケープする。初期値は初回表示専用とし、エラー再表示や未選択POSTを初期値で埋めない。項目キーをメールタグと共有する。

## 実装記録（2026-09-28）

- `OMF::render_form()` で連携済みフォームを自動描画。任意のフォームIDは連携設定との一致確認に使用する。入力・確認・完了は同じページで処理し、確認省略を管理画面で選択できる。
- 基本10種類、初回のみの初期値、入力エラーと項目の関連付け、添付名、確認から戻る、送信後の新規入力を実装。
- POSTを `omf_fields[項目キー]` にまとめ、`name` 等とWordPress公開クエリ変数の衝突を回避。確認後はセッションの内容を使い、本文・添付の差し替えを受け付けない。
- 既存のCAPTCHA・アップロード・メール送信・部分成功再試行を共用。旧コード方式は維持する。
- 専用CSSは `.omf-managed` 内に限定。テーマ側で上書き可能。
- HTTP結合40項目成功。実Chromeで管理画面の項目名変更→公開側反映、375pxの入力・確認画面を確認。その時点では完了画面と768/1440pxが未確認（下記の完了検証で確認済み）。実SMTP/実CAPTCHAサービスは未確認。外部サービスはOMF-010で検証する。

## 設置コード

設置先の固定ページで「メールフォーム連携」を選び、そのページを描画するテーマに次の1行を置く。フォーム項目ごとのHTMLは不要。

```php
<?php \Sharesl\Original\MailForm\OMF::render_form(); ?>
```

テーマは通常どおり `wp_head()` と `wp_footer()` を呼ぶ。入力・確認・完了用の固定ページを別々に作る必要はない。旧方式からの切替は管理画面で方式を選び保存して行う。
