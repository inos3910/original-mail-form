## 概要

改修前の入力・確認・完了ページの遷移と表示制限を復元する。PHP・ブロック・ショートコードすべてで設定された専用URLを使用し、管理画面による項目編集と元のデザインを維持する。

承認済みの修正とローカル反映・検証を実施した。[検証記録](../guide/verification-20261001-flow.md)を参照。利用者のレビューとOMF-010の最終判断を待つ。

## 背景・目的

管理画面方式で、ページ設定を使わず同一URLのセッション状態で画面を切り替える処理が追加された。そのため `/contact/` に確認・完了が表示され、完了後のリロード・再訪でも完了が残る。既存の画面遷移とセッションの寿命を損なっている。

改修前の基準は west-japan-family のプラグイン。確認は認証済みセッションがあればGETでも表示でき、完了は初回表示で対象フォームのセッションを消す。新実装では、必要な表示情報をリクエスト内の変数へ退避してからセッションを破棄し、その変数で完了を描画する。

## 要件

### 画面の表示条件

| 画面 | 表示条件・データの寿命 |
| --- | --- |
| 入力 `/contact/` | 通常アクセス・リロード・再訪は初期化。認証済みの「修正」操作から戻った直後だけ入力値を保持 |
| 確認 `/contact/confirm/` | 検証済み入力と有効な認証がある場合だけ表示。認証済みセッションがあればGET・リロードも許可。それ以外は入力URLへリダイレクト |
| 完了 `/contact/complete/` | 正常な送信後の遷移だけ許可。表示情報を変数へ退避し、セッションを破棄して1回だけ描画。リロード・再訪・直接アクセス・不正POSTは入力URLへリダイレクト |
| 確認省略 | 入力→送信→完了の2ページ。入力初期化・完了の単回表示は同じ条件を適用。確認ページへのアクセスは入力URLへ戻す |

- 上記URLはセキュリティサイトの設定例。他のフォームは管理画面で設定したURLを使用する。
- 入力エラー・送信エラーの直後は、訂正に必要な値とエラーを1回表示する。その後の通常リロードでは初期化する。
- 通常ページへの遷移では既存セッションがある場合に対象フォームの状態を初期化する。フォーム未利用者、REST・静的ファイルで新しくセッションを開始しない。
- 現在のURLから画面を判定し、セッションの状態だけで別画面を表示しない。
- 認証はnonce・送信トークン・操作・現在の画面を照合する。POSTがあるだけでは確認・完了の表示を許可しない。
- 確認後の送信は検証済みセッションを使用する。POSTによる本文・添付の差し替えを許可しない。
- 有効なPOSTの処理後は303で設定先へ遷移し、リロードによるPOST再送を避ける。

### 完了画面の処理順序

1. 正常な送信による完了表示許可を確認する。
2. 表示に必要な検証済みデータ・フォーム情報を、そのリクエスト内の変数へ退避する。
3. 対象フォームの入力・認証・エラー・戻るフラグ・完了許可・送信トークンをセッションから削除し、変更を保存する。
4. 見出し・完了文・必要な値は退避した変数から描画する。

- `OMF::form_step()` と描画処理は同じリクエスト内の表示情報を参照する。既存の値取得APIも完了応答内では退避した値を参照できるようにする。
- 完了描画でセッション・送信トークンを再作成しない。完了のボタンは「トップページへ戻る」とし、トップURLへの通常リンクを表示する。ボタンの見た目は維持する（2026-10-01の利用者追加指示）。
- 他プラグインのセッション、配送キュー・送信記録は削除しない。非同期配送に必要な添付も保持する。
- 非同期の完了条件は配送データの永続保存成功で、文言は受付完了とする。保存失敗では完了へ進まない。SMTP配送済みとして扱わない。
- キャッシュ禁止ヘッダーと履歴キャッシュ復元時の再読み込みにより、セッション破棄後の確認・完了表示が復活しないようにする。

### 全設置方式と互換性

- PHP・ブロック・ショートコードは同じ専用URLと表示条件を使用する。入力・確認・完了で同じフォームを指定する。
- 状態・トークンは入力・確認・完了で共有できる対象フォーム単位に管理する。現在の埋め込み用ページ単位の接頭辞では遷移先と共有できないため、見直す。
- 必須ページは確認ONで3ページ、確認省略で2ページ。設定不足・重複・各ページのフォーム指定不一致を検証し、送信を許可せず管理画面に不足内容を表示する。
- 同一URL方式への自動切り替えや、別ページの自動生成は行わない。
- 公開APIの呼び出し方は維持する: `OMF::render_form(['slug' => 'contact'])`、`[omf_render_form slug="contact"]`、既存のフォームブロック。
- 入力画面のforeachによるカンプ再現、管理画面による項目追加・削除・順番変更・ラベル改行・同意編集は維持する。
- 3画面は独立したテーマテンプレートで構築できる。`OMF::form_context()` で動的データだけを取得し、確認値は項目単位の標準描画を再利用する。同意も管理設定順で表示する。見出し・外枠・操作・トップへのリンクはテーマ側で自由に実装する（利用者追加指示）。
