# 共通の項目定義（版1）

OMF-002で定義・検証基盤を実装した。項目編集UIはOMF-003で実装済み（実編集画面での最終確認待ち）。描画APIはOMF-004で追加する。描画APIの導入前に既存サイトの方式を切り替えない。

## 既存フォームとの互換性

- `cf_omf_form_mode` が `builder` のときだけ管理画面方式。未設定を含むそれ以外は `code` とし、従来の `cf_omf_validation` を使用する。
- 旧定義の自動移行・上書きはしない。読み取りによるDB変更も行わない。
- 管理画面方式の定義は `cf_omf_field_schema` に保存する。未知の版・空の項目一覧・不正定義では受付を止め、旧設定には戻さない。
- 入力検証、添付項目の判定、個人情報エクスポート/削除時のメール項目検索は `OMF_Field_Schema::rules()` を共通で使用する。
- 管理画面方式は未定義のPOST項目を除外する。コード方式の検証設定は受付項目一覧ではないため、未登録の文字列・flatな文字列配列・hiddenを維持する。制御用キーは除外し、単一値項目への配列・ネスト・偽の添付辞書は拒否する。

## 保存形式

```php
[
  'version' => 1,
  'fields' => [
    [
      'key' => 'contact_type',
      'type' => 'select',
      'label' => 'お問い合わせの種類',
      'description' => '該当する項目を選択してください。',
      'placeholder' => '',
      'required' => true,
      'choices' => [
        ['value' => 'consultation', 'label' => 'ご相談'],
        ['value' => 'estimate', 'label' => 'お見積り'],
      ],
      'default' => '',
    ],
  ],
]
```

`fields` の配列順が表示順。順序用の数値を別に持たない。1〜100項目、選択肢も1〜100件。

| 型 | 値・初期値 | 検証 |
| --- | --- | --- |
| text / textarea | 文字列 / 空文字 | 必須 |
| email / tel / url | 文字列 / 空文字 | 必須＋既存の形式チェック |
| select / radio | 文字列 / 空文字 | 選択値の完全一致 |
| checkboxes | 文字列のリスト / 空配列 | 全要素の選択値完全一致 |
| acceptance | `1` または未選択 / 初期選択禁止 | 常に必須、`1` のみ |
| file | 既存のサーバー保管情報 / 初期値禁止 | 許可拡張子・MIME・サイズ・非公開保存 |

- `key` は英小文字で始まる英小文字・数字・アンダースコア（64文字以内）。重複、`omf_` 接頭辞、フォーム制御用名、CAPTCHA項目名を禁止する。
- `label` 必須。管理画面の「項目名（改行できます）」で改行を指定でき、入力・確認画面に反映する。メールの全項目一覧ではラベルの改行を除いて1行にする。ラベル・説明・placeholderはプレーンテキスト2000文字以内。描画時にも文脈に応じてエスケープする。任意HTMLは受け付けない。
- 選択肢の `value` と `label` は200文字以内。値は非空・重複不可。サニタイズで値が変化する定義は保存前に拒否する。カンマと `0` は使用可能。
- 初期値は文字列10000文字以内、複数選択は選択肢の値の配列。選択肢にない初期値を拒否する。同意は事前にチェックしない。
- 初期値は描画専用。POSTの欠落を初期値で埋めて検証に通さない。形式検証は通常の入力経路で行う。
- 添付は `extensions` に許可拡張子のリストを明示する。`max_bytes` は1〜10485760（既定10MiB）、実アップロード時にはWordPress側上限も適用する。危険な拡張子は常に拒否する。

## APIと保存時の責務

`OMF_Field_Schema::normalize($schema)` は正規化した配列または `WP_Error` を返す。エラーコードは `omf_invalid_schema`、データの `field_index` は0始まりの項目位置（全体エラーはnull）。POSTの文字列値からbool/intへの変換、wp_unslash、権限・nonce確認は保存側が行う。

`read($form_id)` は保存された定義を検証して返す。`rules($form_id)` は方式に応じた既存検証形式を返す。`allowed_values` は選択値の配列であり、旧方式のカンマ区切り `matching_char` に変換しない。

OMF-003の保存は、全体を検証してから単一メタの定義を更新する。不正な入力を部分保存しない。管理画面方式の選択前に定義が有効であることを確認する。フォーム方式・確認画面設定は項目定義に混ぜず別メタで保存する。

## 項目キーとメールタグの保護（OMF-003で実装）

- 新規追加時だけキーを入力でき、保存済みキーは編集不可。ラベルや順番の変更はキーに影響させない。
- メール設定で使う `{key}` と保存データのキーは同じ。選択肢ラベルとは別に、メールには従来どおり送信値を渡す。表示ラベルへの変換は後続フックで扱う。
- キー変更は削除＋新規追加として扱う。削除候補が自動返信/通知の宛先・件名・本文・From・Reply-Toのタグに使われていたら保存を拒否し、該当設定を示す。フォーム全体のメール設定更新と整合させる。
- コード方式から自動でHTMLの項目や型を推測しない。管理画面方式への切り替えは明示操作とし、旧設定を残す。切り替えによって旧テンプレートの動作が変わることを説明する。

## 一括設定と共通バリデーション（2026-09-30）

管理画面の「都道府県」は47件入りの選択リストを追加する。既存の選択項目では「選択肢をまとめて追加」で1行1件の貼り付け、都道府県47件、海外の追加ができる。既存値を残し、重複は追加しない。上限100件。追加後に表示名・送信値を個別編集できる。

文字入力の `max_length`、文字入力の `min_length` とtext/textareaの `validation_format` を設定できる。形式は numeric / alpha / alphanumeric / katakana / hiragana / kana / postal_code / date。email / tel / url型は型に応じた形式を自動適用する。日付は実在するYYYY-MM-DD / YYYY/MM/DD / YYYY年M月D日（曜日の括弧表記も可）、URLはhttp/https、電話は国内番号（全角数字とハイフンを許可）。メールはASCIIの一般的なメールアドレスを受け付ける。

管理方式ではPHPが共通検証定義を生成し、`data-omf-validation` に同じ条件を出力する。文字数はUnicode文字数で数える（絵文字も1文字）。ブラウザ標準のmaxlengthはUTF-16単位で判定が異なるため使わない。必須・条件付き必須・選択値・添付の拡張子/容量も両側で検証する。添付の中身・CAPTCHA・nonce・権限等の安全性は常にサーバー側で検証する。

フォーム設定の「入力中のJS検証」でON/OFFを切り替える。OFFでもPHP検証は有効。コード方式の手書き項目は `data-validate="required|email"`、`minLength:2|maxLength:100` 等で入力補助を使える。管理方式の共通条件は既存コード方式の検証仕様を変更しない。

同意項目の `policy_text` に規約本文を入力すると、チェック欄の前にスクロールできる本文領域を出力する。本文は2000文字以内。説明文の `[個人情報保護方針](/privacy/)` は安全なリンクとして表示する。

住所連携は `address_targets` に full（1行）または prefecture / city（分割）の項目キーを保存します。同一キーへの重複連携・対象不在・対象型不一致は保存前に拒否します。[住所項目の使い方とデータ更新](../guide/postal-address.md)を参照。
