# 添付ファイルの非公開保存先

添付の保存・旧添付の取り込み時だけ保存先を作成する。定期掃除、添付参照、設定画面表示、設定保存ではフォルダ・保護ファイルを作らない。未作成の参照結果は空文字、掃除は何もせず終了する。

## 保存先と互換性

優先順位は `OMF_PRIVATE_UPLOAD_DIR` 定数、`omf_private_upload_directory` オプション、旧 `omf-{ABSPATHのSHA-256先頭16文字}` 配下の既存添付、自動選定。既存添付は自動移動・改名しない。新規フォルダ名は `original-mail-form-private-attachments-{サイトのフォルダ名}-{識別子16文字}`。

自動選定はWordPressの隣、WordPress/PHPの一時領域を候補とし、検出できた公開領域外かつ書き込み可能な場所を使う。一時領域はOS・サーバー側で削除される可能性がある。長期間保持する添付を利用する場合は、サーバー管理者が永続的な専用フォルダを指定する。

「設定 → 一般」の「添付ファイルの保存先」は、通常表示をフォルダ名と未作成／作成済み／使用不可の状態に限定する。絶対パスは「保存先の詳細設定」を開いたときだけ表示・指定できる。定数指定時も絶対パスは詳細設定内だけに表示する。折りたたみは画面共有時などの露出を減らす表示上の配慮であり、権限制御の代わりではない。空欄は自動選定。親フォルダは事前作成が必要。設定保存ではパスだけを保存し、旧フォルダは削除しない。定数指定時は管理画面で変更できない。

添付や他のファイルがある場合は保存先の切り替えを拒否する。保存元・保存先とも、空または保護・説明ファイルだけであることが必要。添付保存と設定変更はDBのオプションによる共通ロックで排他する。ロック期限は5分で、期限切れ回復・解除は値も照合する。エクスポート対象には含めない。

## 配信とアクセス制御

保存先は絶対パスで、親フォルダが存在し、フォルダ自体がシンボリックリンクでないことが必要。実パスでWordPressルート、`DOCUMENT_ROOT`、`CONTEXT_DOCUMENT_ROOT` 内を拒否する。Herd/Valetの設定を検出できた場合はpark対象の親ディレクトリ全体とその直下のサイトリンク先も拒否する。

既知の別サイト・エイリアスの公開ルートを追加する場合は、全リクエストで読み込まれる場所に次を置く。

```php
add_filter('omf_additional_public_directories', static function (array $roots): array {
    $roots[] = '/srv/another-public-root';
    return $roots;
});
```

すべてのサーバー設定・別名URLを自動検出する保証はない。サーバー管理者が配信対象外であることを確認する。公開領域と判定した既存保存先も、黙って新しい場所へ切り替えず使用不可にする。添付参照は空文字、新規保存はエラー、掃除は停止する。添付が残っているときは切り替えを拒否するため、既存ファイルを保全した上で、サーバー管理者による移設と設定変更が必要になる。

初回保存時にフォルダを0700、添付と説明・保護ファイルを0600に制限する。`README.txt` に用途・サイト識別子・管理画面での確認方法を記載する。`.htaccess` は `Require all denied` とし、Apacheで対応する設定が有効な場合の追加対策にする。Nginxは `.htaccess` を解釈しない。公開領域への配置をこのファイルだけで許可することはしない。既存の説明・保護ファイルが異なる場合は上書きせず保存を拒否する。
