## 2. 項目を編集する

1. デモの管理画面入口を開きます。フォーム編集画面が表示されれば成功です。
2. 「フォーム」タブを開きます。項目の一覧とプレビューが表示されれば成功です。
3. 本文の項目を選び、ラベルを「お問い合わせ内容」に変えます。プレビューの見出しが変われば成功です。
4. 項目追加から任意の入力欄を追加します。一覧の最後に追加されれば成功です。
5. 項目の並べ替えハンドルをドラッグします。ドロップ先へ移動すれば成功です。
6. 「更新」（英語表示では「Update」）を押します。保存後に同じ内容・順番が残れば成功です。
7. 公開フォームを再読み込みします。追加と並べ替えが反映されれば成功です。
8. 追加した試験項目を削除して更新します。公開側から消えれば成功です。

メールで参照中の項目は削除できません。エラーで戻った際に編集中の内容が残ることも確認してください。項目ごとのPHPやHTMLを書き換える必要はありません。初回の設置方法は「9. ページへの設置」を参照してください。

## 3. 投稿・固定ページのIDを選ぶ

1. 「その他の設定」の表示条件を開きます。IDを指定する欄に検索入力とタグが表示されれば成功です。
2. 「タイトルで検索、またはIDを入力」に固定ページ名を入力します。候補が表示されれば成功です。
3. 候補を選びます。選んだIDがタグになれば成功です。
4. 別の固定ページIDを数字で入力し、Enterを押します。検索せずタグになれば成功です。
5. タグの削除ボタンを押します。そのIDだけ消えれば成功です。
6. 保存して再表示します。残したIDだけ復元されれば成功です。

この設定は従来のページ連携方式で使用します。ブロック・ショートコード方式は本文で選んだフォームが優先され、ページ連携は不要です。確認後は元のIDへ戻してください。

## 4. 入力・確認・完了

1. 公開フォームを開きます。完了画面が残っている場合は「新しいお問い合わせ」を押します。10種類のサンプル項目が表示されれば成功です。
2. 必須項目を空にして「入力内容を確認」を押します。送信せず入力エラーになれば成功です。
3. メールと本文を入力し、同意を選びます。「入力内容を確認」で確認画面へ進めば成功です。
4. 「入力内容を修正」を押します。入力した値が残れば成功です。
5. 許可された小さなtxtファイルを添付して確認へ進みます。確認画面にファイル名が表示されれば成功です。
6. 「送信する」を押します。「送信が完了しました」が表示されれば成功です。
7. 完了画面を再読み込みします。再送されなければ成功です。
8. 「新しいお問い合わせ」を押します。新しい入力を開始できれば成功です。
9. 管理画面で「送信前の確認」を「確認を省略して送信」に変えて更新します。公開側が「送信する」となり、確認を挟まず完了すれば成功です。
10. 管理画面で「確認画面を表示」に戻します。確認画面が復活すれば成功です。

## 5. 送信方式を切り替える

フォーム編集の「その他の設定」→「送信方法」で選び、「更新」（英語表示では「Update」）で保存します。

### 同期・直列（標準）

1. 「同期・直列（標準）」を選び保存します。
2. 公開側から1件送信します。送信結果を待って完了すれば成功です。

### 同期・並列

1. 「送信状況・環境確認を開く」を押します。
2. 「並列送信の環境を確認」を押します。「環境確認済み」と表示されれば利用できます。利用不可の場合は直列を使います。
3. フォーム編集で「同期・並列」を選び保存します。
4. 公開側から1件送信します。完了後、送信状況の自動返信と通知メールが両方「送信成功」なら成功です。
5. 通知本文に `{omf_reply_mail_sended}` を入れて保存を試します。理由付きで保存を拒否すれば成功です。確認後はタグを削除します。

### WordPressで非同期

1. 「WordPressで非同期」を選び保存します。実行時刻を保証しない説明が読めれば成功です。
2. 公開側から送信します。「お問い合わせを受け付けました」と表示されれば成功です。
3. 公開側のタブを閉じます。
4. 「送信状況」を開きます。受付が残っていれば成功です。
5. ローカルデモでは「WordPressの送信待ちを今すぐ処理」を押します。両通が「送信成功」へ変われば成功です。
6. 実環境では手動実行せず自動処理を待ちます。最終実行日時と両通の結果が更新されることを確認します。

ローカルデモは外部HTTPを遮断しているため、WordPressの自動起動そのものは実環境で確認します。低アクセスやループバック制限では送信待ちになる可能性があります。

### サーバーcronで非同期

1. 「サーバーcronで非同期」を選びます。cron設定例が表示されれば成功です。
2. 設定例のWP-CLIパスを、検証サーバーに実在する絶対パスに置き換えます。
3. そのコマンドをターミナルで1回実行します。「送信待ちを処理しました」と表示されれば成功です。
4. サーバーのcron設定に1分間隔で登録します。
5. 公開側から1件送信します。受付完了になれば成功です。
6. 「送信状況」を開きます。サーバーcronの最終実行日時が更新され、両通が成功すれば成功です。
7. 確認後、不要な試験用cron設定を削除します。

cronの登録画面とWP-CLIのパスはサーバーごとに異なります。画面の例を無修正で登録しないでください。ローカルデモのWP設置先は起動ごとに変わるため、設定画面に表示された `--path` を使います。

## 6. 失敗したときの操作

1. 「送信状況」で対象の受付番号を探します。
2. 「自動返信」と「通知メール」のどちらが失敗したか確認します。
3. SMTPの設定・制限を確認して直します。
4. 「失敗したメールを再試行」を押します。成功済みのメールが再送されず、失敗したメールだけ成功へ変われば成功です。

「結果不明」は、送った後で記録できなかった可能性があります。再試行ボタンは表示しません。SMTPログと受信先を調べ、独自に再送する場合も重複の有無を先に確認してください。

「DB保存・外部連携」が結果不明のときは、メールの再送でやり直さず、DB・Slack・Sheets側を確認します。

## 9. ページへの設置（初回のみ）

### ブロックで設置する（FSE・通常テーマ共通）

PHPやHTMLを書く必要はありません。フォームは投稿・固定ページの本文に設置します。

1. 「メールフォーム」で設置するフォームを開きます。
2. 作成方法を「画面でかんたんに作成」にします。
3. 必要な項目とメール設定を保存します。
4. フォームを公開します。「ページに設置する」欄に案内とコピー欄が出れば準備完了です。
5. 設置先の投稿・固定ページを編集画面で開きます。
6. 本文の「＋」から「お問い合わせフォーム」ブロックを追加します。
7. 「設置するフォーム」にフォーム名を入力します。検索候補が出れば成功です。
8. 候補からフォームを選びます。入力欄の見本が出れば成功です。
9. 投稿・固定ページを保存します。
10. 公開ページを開きます。入力欄と「入力内容を確認」が表示されれば設置完了です。

以後、項目を変更する場合はブロック下部の「フォームの項目を編集 ↗」から編集します。フォームの保存後、公開ページを再読み込みすると反映されます。編集中のページは先に保存してください。

### ショートコードで設置する

1. フォーム編集画面の「ページに設置する」で「コピーする」を押します。「コピーしました」と表示されれば成功です。
2. 投稿・固定ページ本文にWordPress標準の「ショートコード」ブロックを追加します。
3. コピーした文字を貼り付けます。`[omf_render_form slug="contact"]` のような表示になります（スラッグはフォームごとに違います）。
4. 投稿・固定ページを保存します。
5. 公開ページを開きます。フォームが表示されれば設置完了です。

### 設置後の確認

- 同じフォームを2ページに設置し、それぞれ別の本文で確認画面へ進みます。入力内容が混ざらないことを確認します。
- 同じページにブロックとショートコードを両方設置すると、1つだけにする案内が表示されます。片方を削除して保存してください。
- フォームを非公開・削除・コード方式へ変更すると設置できなくなります。公開済みの管理画面方式フォームを選び直してください。
- グループ内・同期パターン内でも設置できます。サイトエディターのテンプレート/パーツへの直接設置、クエリーループ内への設置は対象外です。
- 編集画面は入力欄の見本です。実際の確認・送信は公開ページで行います。

### 既存のPHPテンプレートへ設置する場合

設置先ページの「メールフォーム連携」で対象フォームを選び、テーマに次の1行を置きます。入力・確認・完了で同じ1行を使います。

```php
<?php \Sharesl\Original\MailForm\OMF::render_form(['slug' => 'contact']); ?>
```

ショートコードの1行を使う場合は `<?php echo do_shortcode('[omf_render_form slug="contact"]'); ?>` です。テーマは `wp_head()` と `wp_footer()` を呼ぶ必要があります。ブロック・ショートコードとPHP関数を同じページへ重ねて設置しないでください。旧コード方式のフォームは切り替えず使用できます。

## 追加の確認：一括入力・同意本文・PHP/JS検証

ローカル既存サイトは [お問い合わせ](https://fam-security-wp.test/contact/) で確認できます。実送信は実際の宛先にメールが届きます。入力エラーと確認画面までのチェックは送信されません。

1. 管理画面でフォーム「お問い合わせ」を開きます。
2. 「入力中のJS検証」をONにします。
3. 項目の「編集」を開き、「バリデーション」で文字数・形式を設定します。
4. 保存します。
5. 問い合わせ画面で条件に合わない値を入力します。入力欄の下にエラーが出れば成功です。
6. 正しい値に変更します。エラーが消えれば成功です。
7. 「入力中のJS検証」をOFFにして保存します。
8. 同じ不正な値で「入力内容を確認」を押します。PHP側でもエラーが表示され、確認画面へ進まなければ成功です。
9. 検証に使った文字数・形式を元の設定へ戻して保存します。

選択肢の確認は、検証用フォームで行うと既存フォームに影響しません。

1. 「都道府県」を押します。47件の選択リストが追加されれば成功です。
2. 選択項目の編集で「選択肢をまとめて追加」を開きます。
3. 1行1件の選択肢を貼り付けます。
4. 「貼り付けた選択肢を追加」を押します。既存値を残して新しい値が増えれば成功です。
5. 同じ内容を再度追加します。重複が増えなければ成功です。

同意項目は「同意前に表示する規約・方針の本文（任意）」に本文を入れると、チェック欄の前に表示されます。リンクは説明欄に `[個人情報保護方針](/privacy/)` と入力します。

既存サイトでは確認画面の見出しが「入力内容の確認」に変わり、電話案内は非表示になります。完了画面の同じ切り替えとメール到着は、最終の実送信確認で確認してください。


## 追加修正の確認：確認画面・入力初期化・住所

既存サイトの電話番号は任意です。「必ず電話」を選んでも番号を必須にしません。

1. 問い合わせ画面を開きます。連絡方法のラベルが左、選択肢が右に並ぶことを確認します。
2. 電話番号を空欄にし、他の必須項目だけ入力して確認画面へ進みます。
3. 確認画面で、必須ラベルが表示されず、本文に入力欄風の枠がないことを確認します。
4. 同意欄が他の項目と同じ「個人情報保護方針への同意 → 同意する」の並びであることを確認します。
5. 「入力内容を修正」を押します。入力値が残れば成功です。
6. 入力画面を再読み込みします。入力値が初期状態に戻れば成功です。管理画面で初期値を指定した項目は、その値に戻ります。
7. 不正なメールアドレスで確認へ進みます。エラー直後は入力値を保持します。その後の再読み込みでは値とエラーが消えることを確認します。
8. 入力画面から別ページへ移動して戻ります。古い入力値が復元されなければ成功です。

文字入力の「バリデーション」は折り畳まず表示します。ひらがな、カタカナ、ひらがな or カタカナ、半角英字、半角英数字、半角数字、日付、郵便番号が選べます。各形式で適合値・不適合値を入れ、JS検証ONとOFFの両方で確認します。

住所の追加と自動入力は[住所項目の手順書](postal-address.md)を参照してください。既存お問い合わせには住所欄を勝手に追加していません。必要なフォームにプリセットを追加して利用します。


## 郵便番号データを管理画面から更新する

- [ ] 「メールフォーム」→「設定」に現在の件数・データ更新日（取得後は取得日時）・最新確認日時が表示される。
- [ ] 「郵便番号データを更新」を押すと、処理中のボタンは再度押せなくなる。
- [ ] 成功すると「更新しました」または「すでに最新です」が表示され、確認日時が更新される。
- [ ] 更新後も郵便番号 `1000001` で東京都千代田区千代田が入力できる。
- [ ] 通信失敗、不正なZIP、二重実行では既存データを変更しない（自動試験で確認）。

詳しい操作と必要なサーバー環境は [postal-address.md](postal-address.md) を参照。


## 入力条件によるボタン制御・メールの初期文面

- [ ] JS検証ONの入力画面では、必須欄が空の間、確認／送信ボタンが無効になり理由が表示される。
- [ ] 入力条件をすべて満たすとボタンが有効になる。任意欄への不正入力でも無効になる。
- [ ] 条件付き必須の切り替え、住所自動入力、確認から戻る操作にもボタンが追従する。
- [ ] JS検証OFFではこの無効化を行わず、送信時のPHP検証を使う。
- [ ] 新規フォームの自動返信・通知には標準の件名・本文が表示される。
- [ ] 既存フォームの文面は変わらない。「空欄に標準の件名・本文を入れる」は未入力欄だけを埋める。
- [ ] 管理画面方式では `{form_data}` が全項目を順序どおりのラベルと表示値でメール本文に展開する。

ローカルサイトの全項目確認フォームは [form-check](https://fam-security-wp.test/form-check/) 。入力例・確認手順は [local-form-check.md](local-form-check.md) を参照。


## メール本文のタグ説明

- [ ] 自動返信・通知の本文欄の下に、元と同じ補足説明としてタグ一覧が表示される。
- [ ] `{form_data}` の用途・管理画面方式限定・項目変更への追従を確認できる。
- [ ] 個別項目、送信日時、メールID、サイト名、URLの説明が、薄い背景・細い枠・内側の余白でまとまっている。大きな見出しはなく、本文欄の補足として読める。

## カンプ用入力テンプレート・完了メッセージ

- [ ] `/contact/` のラベル、連絡方法の改行、選択肢、同意欄、ボタンが元カンプの配置になっている。
- [ ] 管理画面で項目を並べ替えると入力画面にも反映する。同意欄は一覧の下・ボタンの上に残る。
- [ ] 必須項目と同意を入力すると確認ボタンが押せる。電話番号は空欄でも進める。
- [ ] 確認画面では同意が「個人情報保護方針への同意：同意する」と他の項目と同じ並びで表示される。戻ると値が残る。
- [ ] メールフォーム編集の「フォーム」タブ末尾の「完了画面のメッセージ」を編集して保存できる。
- [ ] 送信後、設定した完了メッセージと改行が表示される。空欄なら従来の既定メッセージになる。

## 管理画面での項目変更とカンプ用テンプレート

- [ ] 各項目の「編集」→「項目名（改行できます）」でEnterを入れ、保存するとその位置で改行される。
- [ ] 通常項目の名前・説明・placeholder・選択肢・必須・検証設定の変更と追加・削除・並べ替えが反映される。メールタグで使用中の項目の削除は、参照タグを先に変更する。
- [ ] 同意項目を2つ以上追加すると、同意項目だけが管理画面での相対順序を保ってボタン上に並ぶ。
- [ ] 同意の説明に `[利用規約](https://example.org/terms/)` を入れると外部リンクになる。内部リンクや規約本文も同様に指定できる。
- [ ] 確認画面は同意を移動せず管理画面の全体順序で表示する。メールのラベルは改行なしで表示する。
