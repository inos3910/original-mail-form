# サーバーcronの設定（サーバー共通）

「サーバーcronで非同期」は、お問い合わせを保存した後、サーバーの定期実行でメールを送る方法です。WordPressのアクセス数に頼らず起動できます。サーバーへの登録はこの手順で1回行います。

## 用意するもの

- WordPressの管理者アカウント。
- サーバー管理画面の「cron」「定期実行」を登録する権限。
- HTTPSで公開されたサイトと、サーバーで使えるcurl。

WP-CLIやWordPressの設置パスは不要です。コマンドを登録できないサーバーやcurlが使えない環境では、サーバー管理者へ確認してください。外部のURL実行サービスへ秘密のコマンドを渡す手順ではありません。

## 登録する

1. WordPress管理画面で「メールフォーム」→「送信状況」を開きます。
2. 「サーバーcronの設定」の「登録用コマンドをコピー」を押します。「コピーしました」と表示されれば準備完了です。
3. サーバー管理画面で「cron」「定期実行」を開きます。名称はサーバーによって異なります。
4. 新しい設定の実行間隔を「1分ごと」にします。
5. 「コマンド」欄へコピーした内容を貼り付けます。
6. サーバー管理画面で保存します。
7. WordPressの「送信状況」を開き直します。「サーバーcronの最終実行」の日時が更新されれば、起動を確認できています。

分・時・日・月・曜日を別々に入力する画面では、5つすべてに `*` を入れます。時刻とコマンドを1行で入力するcrontabでは、手順2で「crontab形式をコピー」を使います。コマンドだけの欄へcrontab形式を貼り付けないでください。

日時の更新だけではメール到着の確認になりません。テスト用フォームを「サーバーcronで非同期」に保存し、指定した試験用宛先で1件送信して、「自動返信」「通知メール」と実際の受信箱を確認してください。自動返信OFFでは通知だけを確認します。既に待機中のメールがある場合、cronの登録後にそれらも処理されます。

## 日時が更新されないとき

1. 「送信状況」で「接続確認用コマンドをコピー」を押します。
2. サーバーのコマンド実行画面、またはサーバーへ接続したターミナルへ貼り付けます。
3. コピーしたコマンドを1回実行します。この確認ではメールを送りません。
4. WordPressの「送信状況」を開き直します。「接続確認の最終成功」が更新されれば、接続と認証は成功しています。
5. 接続確認だけが成功する場合は、サーバー側の実行間隔・登録したコマンド・cronのエラーログを確認します。

curlがない、実行パスの指定が必要、SSLエラー、Basic認証・WAF・IP制限でサイトへ接続できない場合は、サーバー管理者へ確認します。証明書の検証を無効にするコマンドへ書き換えないでください。

WP非同期とサーバーcronは同じ配送処理を使いますが、起動方法と対象の待機データが異なります。WP非同期の成功だけでは、サーバーの定期実行が動く保証にはなりません。コマンドの呼び出しはHTTPでWordPressのWeb環境に入り、従来のCLI実行によるPHP環境の違いを減らします。従来の `wp --path=... omf delivery run` も使えます。

## キーを再発行する・定期実行を止める

コピーしたコマンドにはこのサイト専用の登録用キーが入っています。公開・共有しないでください。キーは画面やURLに表示せず、コマンドをコピーしたときだけ管理者へ渡します。

キーを変更するときは「設定できない場合・登録用キーの管理」→「登録用キーを再発行」を押します。再発行後は登録用コマンドをコピーし直し、サーバー側の設定も更新してください。古いコマンドでは起動できなくなります。

定期実行を止める場合は、サーバー管理画面から登録したcron設定を削除します。送信方式を変えても、既に受け付けたメールの方式は変わりません。未送信の受付が残っている間に止めると、そのメールは送信待ちになります。

WordPress公式の背景説明：[WP-Cronとサーバーの定期実行](https://developer.wordpress.org/plugins/cron/hooking-wp-cron-into-the-system-task-scheduler/)。このプラグインのHTTP起動はOMFのサーバーcron用受付だけを処理し、WordPress全体の定期処理を置き換えません。
