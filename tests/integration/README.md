# 隔離WordPressのHTTP結合試験

既存サイトのWordPress本体を読み取り専用で利用し、一時ディレクトリ・ランダム名の専用DBに試験サイトを構築する。既存サイトの設定・DB・テーマ・プラグイン配置は変更しない。

## 実行

PHP 8.1以降、Python 3、WP-CLI、mysqlコマンド、起動済みのローカルMySQLが必要。DBの作成・削除権限を持つパスワードなしのローカル試験ユーザーを使用する。既存サイトの資格情報は読み込まない。

```sh
python3 tests/integration/run.py \
  --wordpress-core /path/to/local/wordpress \
  --mysql-socket /path/to/local/mysql.sock
```

必要なら `--mysql-user` を指定する。専用DB・HTTPサーバー・添付・PHPセッションは終了時（通常の例外を含む）に破棄する。強制終了や電源断では残る可能性があるため、`omf_integration_` で始まるDBと `omf-wp-integration-` で始まる一時ディレクトリを確認する。既存DBは削除しない。

## 検証範囲

- 実WordPressのフック・DB・nonce・Cookie・セッションとHTTPのPOST/リダイレクト。
- 通常ページのセッション抑制、確認画面への直接POST、入力エラーと本文保持。
- PHP・ショートコード・ブロックの専用入力→確認→送信→完了URL、認証済み確認GET、完了の単回表示、使用済みトークンと競合POSTの再送。
- 3画面の独立したテーマテンプレートとHTMLを出力しない `form_context()`、完了メッセージだけの自動描画。
- 完了情報の退避と値取得API、描画後のセッションファイルからの状態・トークン消去、他プラグインと別フォームの保持。
- 確認省略の2ページ、設定不足・重複・フォーム不一致、通常ページでの初期化、favicon・REST・静的ファイル取得での状態維持。
- 非同期の永続保存失敗、セッション消去後の添付配送。故障注入で想定したDBエラーだけを分類し、他の警告・例外を末尾で検出する。
- 自動返信/通知の片方失敗と再試行、成功済みメールの二重送信防止、DBの重複防止と結果更新。
- 全設置方式の連携ON/OFF。本文ブロック・ID/スラッグ指定ショートコード・入れ子・同期パターン・投稿でも、3専用ページの途中OFFと認証済みPOSTの拒否、ON復帰・未設定・不一致を確認。
- ページのメールフォーム連携欄。先行フォームの未設定・条件不一致でも判定を継続し、対象ページだけへ表示。ON/OFF保存とnonce・編集権限を確認。
- 認証付きcron HTTP起動。認証なし・GET・旧キーの拒否、接続確認での非送信、サーバーcron用受付だけの処理、重複呼出の再送防止。試験環境はlocal種別とループバックURLでHTTPの例外条件を満たす。
- multipartによる添付の非公開保存、通知のみへの添付、送信後削除、PHP拒否。
- CAPTCHA未通過の拒否、同じ入力の通過記録、通過後の入力改ざん拒否。
- WordPressのデバッグログが空であること。

## 外部境界

`pre_wp_mail` で送信を捕捉し、実メールは送らない。CAPTCHAのHTTP応答はフィクスチャで置換する。その他のWordPress HTTP通信は拒否する。Slack/Sheetsは未設定で、直接curlを使う連携も起動しない。SMTP接続・実受信・CAPTCHAサービス・Google/Slackの実連携・Release更新インストールを検証したことにはならない。

独立した最小テーマを使うため、既存サイトのテーマ表示やブラウザJSの検証は含まない。試験用PHPは `OMF_INTEGRATION_TEST` 定義がない環境では動作しない。これらのファイルを公開サイトへ配置する必要はない。

### 管理画面の手動検証

`--browser-review` を付けるとHTTP試験後に一時サイトを維持する。表示されたローカルログインURLから試験管理画面へ進み、終了時はターミナルでEnterを押す。一時サイトとDBは終了時に削除する。管理画面のPHPが元サイトの設定を参照しないよう、`wp-admin` と `wp-includes` は一時領域へコピーする。ログイン補助は試験フラグ・PHP組み込みサーバー・ループバック接続でのみ動作し、既存サイトには配置しない。
